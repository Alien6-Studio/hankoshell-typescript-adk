# 0.7.0 — Application integration

Milestone: https://github.com/Alien6-Studio/hankoshell-typescript-adk/milestone/1

## Intended experience

Sign in once and keep working when requests move between application replicas or an application restarts. Signing out ends the application session. An expired or denied session offers an explicit recovery action instead of an automatic sign-in loop.

Applications use the public ADK for session storage, renewal and safe access diagnostics. Application-specific account binding and business permissions remain explicit. Active organization selection continues the scope of issue #17.

## Acceptance before publication

- Two independent application instances share encrypted session state and perform one refresh for concurrent requests.
- A restarted instance can continue a valid session. A logout racing a refresh cannot restore it.
- An uncertain refresh outcome never causes the consumed refresh token to be replayed.
- Refresh tokens and logout hints remain server-side; public session output is allowlisted.
- Wrong audiences and malformed, ambiguous or unauthorized organization contexts fail closed with stable diagnostics.
- A packaged reference integration passes the normal quality and release checks before application rollout.

## Delivery status

The candidate implements shared sessions, supported Auth.js callbacks, typed access denials and approved organization selection. Local qualification covers the signed-token/Auth.js/PostgreSQL reference, concurrent independent runtimes, restart, revocation and uncertain refresh outcomes. Publication and installed-consumer rollout remain pending.
